Docker 一张图：存档 · 开的一局 · 配方

治「在我机器上明明能跑」—— 把程序 + 全套环境打成标准件，到哪台机器都原样跑。循序渐进：从空场起点出发，一关一关走到毕业。

git 同构（脚手架）：Dockerfile ≈ 源码 · 镜像 ≈ commit（不可变 · 哈希 · 分层） · 容器 ≈ checkout 出来跑着的工作区 · 仓库 ≈ remote
🎬 开场白：Docker 到底在解决什么（30 秒）
😰 场景：你写好一个网站，自己电脑上跑得好好的。
😱 发给同事 / 部署到服务器：跑不起来——Node 版本不同、缺库、路径不同。这就是那句工程界名言：「在我机器上明明能跑」。
💡 Docker 的答案：把「程序 + 跑起来需要的一切（连操作系统的底子）」打成一个标准包。包搬到哪台机器，跑出来都一样。
这个包体系一共就四个角色——下面三列 + 存档站。绰号只是记忆把手，真实身份见右下「绰号落地表」。

配方Dockerfile项目根目录里一个就叫 Dockerfile 的纯文本文件，一行行写清楚怎么造这个包：拿什么底子、装什么、放什么代码、开机执行什么菜谱 / 新电脑装机清单
存档镜像 Image照配方造好的整个包：你的程序 + 全套环境，内部一层层叠出来，通常几百 MB。躺在硬盘上，是个「死」的只读文件包ghost 系统镜像 / 出厂预装的系统盘
开的一局容器 Container把镜像跑起来得到的活动实例：一个被隔离的进程（任务管理器里能看到的那种），外加一块它专属的可写空间用系统盘启动的一台「临时电脑」——但轻得多，秒开秒删
存档站仓库 Registry集中存镜像的网站，最大的叫 Docker Hub（hub.docker.com，用浏览器现在就能打开逛）应用商店 / GitHub
火化删容器容器被删时，它那层可写改动的磁盘空间直接回收，找不回来（所以重要数据要另想办法放，下一遍讲 volume）网吧电脑重启还原

🚀 为什么「秒开」还省盘

只读层全容器共享：同一个镜像开 10 个容器，磁盘上只读部分只有一份，每个局只背自己那层薄的可写层。开新局 ≈ 读档，不用复制整个游戏。

🔥 为什么容器一删、东西就没了

可写层随容器火化：你这局装的包、改的文件全在可写层里，rm 掉容器它就没了。想让数据活过这一局，要另外挂 volume —— 下一遍再讲。

🧊 为什么存档必须封死

不可变 = 到哪都一样：镜像叠完就锁死（哈希寻址，像 commit），所以任何机器 pull 下来跑出来的东西一模一样。这正是治「在我机器上能跑」的那味药。
