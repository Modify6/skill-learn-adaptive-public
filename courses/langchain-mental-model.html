LangChain：一切皆 Runnable · | 是传送带

治「裸调 SDK 面条代码——模型焊死、提示词焊死、返回值手撕」：从一次最朴素的 LLM 调用出发，装配出 模板→模型→解析 的标准件流水线，再上 RAG 两关与 Agent 导航。基于 LangChain 1.x（create_agent 时代）。

核心定性：LangChain 不生产智能——模型才是发动机，LangChain 是把「调模型」工程化的标准件库：提示词、调用、解析、检索、工具，全部做成可组合零件。  ‖  黄金心智法则：一切皆 Runnable（统一 .invoke 入口）· | 是传送带（LCEL 组合子）；链 = 你写代码时定死的路线，Agent = 模型运行时现场导航。

🔍 为什么不直接用 openai SDK？

一家一个 SDK：鉴权方式、方法名、返回结构全都不一样，换供应商 = 业务重写。LangChain 用统一适配层把厂商差异关进 init_chat_model 的一行模型字符串里，业务代码与供应商彻底解耦。

🎯 链和 Agent 到底怎么选？

唯一判据：处理路线能否在写代码时定死。能定死（检索→生成、翻译、批量打分）→ 用链：快、省、可控；定不死（要查什么、查几步要现场才知道）→ 用 create_agent：灵活，但更贵、更慢、要防跑飞。

🚀 RAG 的「增强」增强在哪？

模型权重里没有你的私有数据，时效知识也补不齐。检索把相关资料塞进 prompt，等于让模型开卷考试：答案基于你的资料、可溯源，资料更新也不用重训模型。
