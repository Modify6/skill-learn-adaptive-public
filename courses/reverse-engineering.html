治「拿到一个黑盒 exe 只会瞎猜」：从一个 16KB 的 license_check.exe 出发（自制教学黑盒，拆自己的锁），走完整取证链——PE 结构 → 导入表 → 字符串 → 反汇编 → CFG → 断点取证 → 字节补丁 → 反编译重建。

核心定性：逆向不还原原稿——编译器把源码降维成机器码（名字/注释/结构全被抹掉），逆向从字节残骸重建「功能等价模型」。  ‖  黄金法则：三层证据链：字节层 → 指令层 → 行为层；锚点定位（导入表 / 字符串 / xref），永远不从第一行通读；静态画地图，动态走实地。

🔍 为什么逆向 ≠ 还原源码？

编译是有损降维：变量名、注释、类型名只在编译器心里，exe 里只剩地址和字节，信息不守恒。逆向的终点是行为等价模型——逻辑等价、名字重起。专家脑子里也是骨架常驻、细节按需重建。

🎯 静态 vs 动态怎么选？

静态 = 画地图：全景、快、可离线、不触发危险行为；动态 = 走实地：真相、可取证，但会真的执行。套路永远是：静态锚点缩小包围圈 → 动态在关键点取证。只会一样，等于只有半把工具。
