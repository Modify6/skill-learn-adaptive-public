C++ 虚函数与多态：静态绑定 · 虚表查寻

治「基类指针调用永远调不到派生类、析构不全引发隐蔽泄漏、多态切片静默失效」—— 从编译器的两难出发，透视 vptr 虚表指针与 vtable 函数地址表的底层协作。

核心两派：静态绑定（无 virtual）＝按指针声明类型在编译期定死跳转地址，0 寻址开销，但多态失效！ ｜ 动态绑定（加 virtual）＝运行时通过对象自带的 vptr 查虚表，同一行代码执行不同实现！  ‖  C++ 价值观：“不为你用不到的东西付费”——普通类对象不带 vptr（省 8 字节且可内联）；声明了 virtual 的类才背负查表开销。
🤔 编译器的两难当你写下 Base* p = ...; p->speak(); 编译器在翻译这行汇编时的抉择
编译期已知条件编译器只知道变量 p 的声明类型是 Base*，根本不知道运行到这一行时 p 究竟指向 Base、DerivedA 还是 DerivedB。
策略一：求快 (默认)编译期定死跳转：直接生成 call Base::speak。零额外寻址、可强力内联；但若 p 指向 Derived，调用结果彻底错误。
策略二：求对 (virtual)运行时动态查寻：让每个对象头部自备 vptr，指令变为 call *vptr[0]。保证正确；代价是对象多占 8 字节 + 一次内存解引用 + 无法内联。
概念 / 术语物理上是什么本质角色核心职责与规矩
vptr（虚表指针）编译器藏在对象内存首部的指针（64位下占 8 字节）“导航指针”在构造对象时由编译器自动注入，指向所属类的虚函数表
vtable（虚函数表）编译器在常量数据区（.rodata）为每个类生成的一张只读函数指针数组类的函数地址簿全类共享一份，记录所有 virtual 函数的真实地址
override 关键字编译期语法注解质检质保卡强迫编译器检查该函数是否真的重写了基类虚函数，防止手滑签名不匹配
virtual 析构函数将析构函数加入虚函数表防泄漏守门员基类指针 delete 时能动态定位到派生类析构函数，保证完整释放
对象切片 (Slicing)值拷贝 Base b = *p; 只复制了基类成员，丢弃了派生类字段与 vptr多态失效陷阱多态只能通过指针或引用生效！传值会导致虚表指针丢失

🔍 为什么普通类不默认带 vptr？

Java 等语言所有对象都有类似开销。C++ 坚持“零开销抽象”：如果一个类只是存三个 int 的简单结构体，它的大小就是 12 字节；一旦加上 virtual，由于 8 字节 vptr 和内存对齐，大小会瞬间翻倍成 24 字节！不要的功能决不强制塞给你。

⚠️ 为什么构造函数中调虚函数没有多态？

对象构造是按层进行的：先构造基类，此刻派生类的成员尚未初始化。在执行基类构造函数时，对象的 vptr 暂时指向基类的虚表！如果此时调到派生类重写的函数并访问未初始化的派生类成员，会导致致命崩溃！

🛡️ 纯虚函数 = 0 的物理本质是什么？

virtual void f() = 0; 的物理本质就是将该类虚表里的该项函数地址填为 nullptr（或指向 __cxa_pure_virtual 报错函数）。既然表里缺了地址，编译器就严禁直接实例化该类！

C++ 虚函数核心链路：类声明 virtual → 编译期生成 vtable 虚表 → 构造时对象首部写入 vptr → 运行时 call *vptr[idx] 动态跳转 ｜ 精准驾驭多态开销
